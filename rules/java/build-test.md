# Java 构建与测试规范

适用场景：修改构建或测试配置、排查构建测试失败，或代码改动进入验证阶段；纯文档修改不要求执行无关工程构建。

仅约束新增代码及本次实质修改的部分，不顺带整改无关存量代码；明确要求规范化整改时按指定范围执行。

## 构建与验证

构建工具固定为 Maven，不引入 Gradle。以下命令均从本工程后端工程目录执行，是按改动范围选择的验证入口，不要求逐条执行，也不代表当前已验证通过。构建状态以本次实际结果为准。
代码变更完成前，执行覆盖受影响模块的构建与相关测试；缺陷修复应增加或更新能覆盖该缺陷的验证。修复本次改动导致的失败后重跑相关检查。最终说明已通过、失败和未执行的检查及原因；未执行或受环境阻塞的检查不得报告为通过。纯文档修改不要求无关工程构建。
启动服务或执行可能访问数据库、消息队列、外部接口的测试前，确认目标环境和副作用范围；不得默认使用生产环境或真实业务数据。目标不明或真实写入超出已有授权时先确认；已确认安全且获授权的本地验证无需逐步重复询问。

```bash
# 检查 Maven 模型（需要父 POM 可解析）
mvn validate

# 需要验证编译、测试和打包时使用
mvn clean package

# 执行全部测试
mvn test

# 验证指定模块及其 reactor 内依赖
mvn -pl aos-{xxx}-provider -am test
```

## 完成与报告

完成以本次请求的行为或交付物已满足、相关验证已执行且结果如实说明为准。与本次改动无关的存量失败只报告，不擅自扩大修复范围；环境阻塞或未完成的验收项须明确列为限制，不得宣称已全部完成。
