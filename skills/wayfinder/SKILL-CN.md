一个松散的想法出现了——规模大到一个代理会话无法容纳，而且笼罩在迷雾中：从这里到**目标**的路径尚不可见。寻路的重点是找到这条路，而不是直接冲向目标。本技能在仓库的议题跟踪器上将路径绘制为一张**共享地图**，然后逐一处理其中的**决策工单**——其解决结果是一项决策，而不是要执行的构建切片——直到路线清晰。

不同工作的目标各不相同，而命名目标是绘制地图的第一步——它会塑造每一个工单。目标可能是一份要移交并持续迭代的规格、一个必须在规划前锁定的决策，或像数据结构迁移一样就地完成的变更。地图与领域无关——工程工作、课程内容或任何符合这种形态的工作都可以。

## 规划，而不是执行

Wayfinder 默认用于**规划**：每个工单解决一项决策；当道路清晰、在有人真正执行之前已没有待决问题时，地图即告完成。想要直接开始做的冲动通常意味着你已经到达地图边缘，应当移交工作。某项工作可以在其 **Notes** 中覆盖此默认值，把执行也纳入地图；否则应产出决策，而非交付物。

## 使用名称引用

每张地图和每个工单都是议题，因此拥有一个**名称**——即标题。在所有给人阅读的内容中——叙述、地图的 Decisions-so-far——都应按名称引用，绝不要只使用裸 id、编号或 slug。满墙的 `#42, #43, #44` 难以阅读；名称则一目了然。id 和 URL 不会消失——名称包裹其链接——但它们位于名称*内部*，不能替代名称。

## 地图

地图是本仓库议题跟踪器中的单个议题，带有 `wayfinder:map` 标签——它是规范制品。地图的工单是其子议题。

地图是**索引**，不是存储库。它列出已作出的决策并指向保存详细内容的工单；一项决策只存在于一个地方——对应工单——因此地图绝不复述，只给出概要并链接。

**地图、子工单、阻塞关系和前沿查询的实际存放方式取决于跟踪器。** 应当已经为你提供了议题跟踪器——如果没有，请运行 `/setup-matt-pocock-skills`。查阅跟踪器文档中的“Wayfinding operations”，了解本仓库如何表达这些内容。如果未提供跟踪器，默认使用本地 Markdown 跟踪器。

### 工单

每个工单都是地图的**子议题**；跟踪器的议题 id 就是其标识。正文是一个问题，规模应适合一个 100K token 的代理会话：

```markdown
## Question

<本工单要解决的决策或调查>
```

每个工单都带有一个 `wayfinder:<type>` 标签——`research`、`prototype`、`grilling`、`task` 之一（参见[工单类型](#工单类型)）。

会话必须在开展任何工作**之前**，先将工单分配给推动地图的开发人员来**认领**它，使并发会话跳过该工单。该受让人就是认领标记：开放且无人负责的工单即未认领。

阻塞使用跟踪器的**原生**依赖关系——这很关键，因为它会在跟踪器自身 UI 中直观呈现前沿，让人无需打开地图就能看到可领取内容。只有缺少原生阻塞能力的跟踪器才回退到正文约定。当阻塞某工单的所有工单都已关闭时，该工单即**解除阻塞**；**前沿**是所有开放、未阻塞、未认领的子工单——已知世界的边缘。

答案不属于正文——它在解决时记录（参见[处理地图](#处理地图)）。解决工单期间创建的制品应从议题中链接，而不是粘贴进去。

## 工单类型

每个工单要么是 **HITL**（human in the loop，人类参与），与能够代表自己发言的人一起处理；要么是 **AFK**，由代理独立推动。HITL 工单只能通过实时交流解决；代理绝不能代替人类回答（自行回答自身问题的 grilling 代理已经破坏了流程）。

- **Research（研究）**（AFK）：阅读文档、第三方 API 或知识库等本地资源，以找出某项决策依赖的事实。由 `/research` **子代理**解决。当所需知识位于当前工作目录之外时使用。
- **Prototype（原型）**（HITL）：制作便宜、粗糙、具体的制品来提高讨论保真度并供人反馈——提纲、初稿、存根，或通过 /prototype 技能生成的 UI/逻辑代码。将原型链接为制品。当关键问题是“应该长什么样”或“应该如何表现”时使用。
- **Grilling（追问）**（HITL）：对话。默认类型。始终调用 /grilling 和 /domain-modeling 技能。
- **Task（任务）**（HITL 或 AFK）：在作出*决策*前必须完成的手工工作——没有需要决定、制作原型或研究的内容，但讨论在它完成前受阻。例如注册服务以评估其 API、配置访问权限、移动数据以观察其结构。这是唯一真正*执行*而非决策的类型——它之所以进入地图，是因为它解锁一项决策，而不是因为它交付目标。代理能独立完成时自行推动（AFK）；否则向人类提供精确清单（HITL）。工作完成即解决；答案记录所做内容以及后续工单依赖的事实（凭据位置、新 URL、行数）。

## 战争迷雾

地图被*有意*保持不完整：不要绘制目前还看不清的内容。现有工单之外是**战争迷雾**——你知道还会出现、但因依赖未决问题而暂时无法精确定义的决策与调查。解决一个工单会清除前方迷雾，把现在能够明确描述的内容逐一转化为新工单，直到通往目标的道路清晰且没有工单剩余。

地图的 **Not yet specified** 部分记录这种模糊视图：未来可能要回答的问题、稍后应重新查看的区域。这是朝向目标但尚未发现的前沿——所有内容都在范围内，只是还不够清晰，无法形成工单。按当前可见程度粗略或完整地记录；它也为协作者指示工作前进方向。

**迷雾还是工单？** 判断标准是现在能否精确陈述问题——*不是*现在能否回答。

- **创建工单**：问题已经清晰——即使它被阻塞、目前无法处理。
- **尚未明确**：还无法如此清晰地表述。不要预先把迷雾切成工单大小；迷雾比工单更粗，等前沿到达时，一块迷雾可能转化为多个工单，也可能一个都不产生。

**Not yet specified** 不包含已经决定的内容（Decisions so far）、已有的开放工单，以及范围之外的内容（下一节）。

## 范围之外

迷雾只会聚集在*通往*目标的方向。目标固定了范围，因此超出目标的工作属于 **Out of scope**——它不是迷雾，也不属于 **Not yet specified**。地图有单独的 **Out of scope** 部分，记录明确排除在本次工作之外的内容。是否进入这里取决于范围，而不是清晰程度。

范围外工作永不转化——前沿在目标处停止——只有重画目标时它才会重新出现，而且应作为一项全新工作，而不是继续旧工作。

排除范围是一项范围决策，而不是路线上的一步。如果一个已有工单后来被发现位于目标之外——绘图时误纳入，或解决其他工单后暴露——应**关闭它**（关闭的工单明确不会出现在前沿），并在 **Out of scope** 中留下一行：概要、排除原因，以及指向已关闭工单的链接。不要把它放入 **Decisions so far**；后者记录实际走过的路线，而范围边界不是路线步骤。

## 调用方式

有两种模式。无论哪一种，**每次会话都绝不能解决超过一个工单**——研究工单除外。

### 绘制地图

用户以一个松散想法调用。

1. **命名目标。** 运行 `/grilling` 和 `/domain-modeling` 会话，明确这张地图要寻找的规格、决策或变更。目标固定范围，因此最先确定。
2. **绘制前沿。** 再次追问，这次采用**广度优先**：横向展开整个空间，而不是深挖一个主题，以发现开放决策和当前可采取的第一步。**如果没有发现迷雾**——通往目标的路已经清晰，整个旅程一个会话即可完成——就不需要地图。停止并询问用户希望如何继续。
3. **创建地图**（标签 `wayfinder:map`）：填入 Destination 和 Notes，Decisions-so-far 留空，并在 **Not yet specified** 中勾勒迷雾。
4. **创建当前能够明确描述的工单**，作为地图的子议题——然后在**第二遍**连接阻塞边（议题必须先有 id 才能互相引用）。连接后，工单被分入前沿或阻塞集合；所有尚无法明确描述的内容留在迷雾——**Not yet specified**。
5. **启动研究子代理。** 对刚创建的每个 `research` 工单，并行启动 `/research` 子代理解决；将发现保存在一次性的 `research/<name>` 分支，并从工单留下上下文链接。
6. 停止——绘图是一整个会话的工作；它本身不手工解决任何工单。

### 处理地图

用户用地图（URL 或编号）调用。工单是**可选的**——如果未指定，由你选择下一个决策，而不是由用户选择。

1. 加载**地图**——低分辨率视图，而不是每个工单的完整正文。
2. 选择工单。如果用户指定了一个，就使用它；否则按顺序选取第一个前沿工单。**认领它**：开展任何工作前先将其分配给自己。
3. 解决工单——**按需放大**：需要时获取相关或已关闭工单的完整正文；调用 `## Notes` 区块中指定的技能。如有疑问，使用 `/grilling` 和 `/domain-modeling`。
4. 记录解决结果：将答案发布为**解决评论**，**关闭**议题，并向地图的 Decisions-so-far **追加上下文链接**。
5. 添加新浮现的工单（先创建、再连接）；把答案使其变得可明确描述的迷雾转化为工单，并从 **Not yet specified** 清除每一块已转化迷雾，使其只存在于新工单中。如果答案揭示某个工单——当前工单或其他工单——位于目标之外，应将其**排除在范围之外**，而不是作为路线的一部分解决。如果决策使地图其他部分失效，则更新或删除那些工单。

用户可能并行运行已解除阻塞的工单，因此应预期其他会话也在并发编辑跟踪器。
